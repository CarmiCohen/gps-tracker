- **ISSUE-NOV11.1-O88 (Low) - What the alarm push does not yet cover**: (1) the relay keeps push tokens in memory only, so after a relay restart a Monitor gets no push until it has rejoined; (2) a push for an alarm type switched off on the Monitor shows nothing, and Android may then lower the app's push priority; (3) if an alert's push is lost and a later alert's push arrives first, `newerReading` hides the earlier alert's relay copy; (4) a push starting a dead session is unit-tested only: on the A15 Android restarted the killed session within 1 s, and a force-stop blocks Firebase; (5) the relay's `uptime_s` during a long session was not recorded (ISSUE-NOV5.1-O9); (6) (Nov11.2-relay) the relay's silence watch is in memory too: after a relay restart a Sensor that never sends again is not reported, and a Monitor whose session is dead hears nothing; (7) the silence push is proved on the A15 only together with the Monitor's own count, which won the race by 1.2 s; (8) (Nov18.12) the setup push is normal priority, which Android may hold while the Monitor's phone dozes, and it is proved live only beside a connected session (227.3, both apps on the A15); a Monitor frozen long enough for the relay to drop its socket (227.4) is covered by `RelayDeliveriesTest` only; Monitors before Nov18.12 ignore the push. Nov19.0: on the S21FE the release Monitor kept its socket with the screen off for 10 min, and `am freeze` does not freeze its foreground-service process, so 227.4 waits for a long natural idle.

## 🚀 Strategic Simplification Ideas
*   **SIMP-NOV23.9-S1**: Drop The Prefix Fallback. Since Nov23.9 the service start, stop and Home Points events carry an `EventEntry.kind`; `isOfKind` in `EventLog.kt` still falls back to the message's start for an event without a kind. Once both phones have run Nov23.9 or later for 7 days, the fallback (and the prefix use in `stopReason`) could go, with the tests of the old wording.
*   **SIMP-NOV22.8-S1**: Fewer Rows While Nobody Watches. **Low priority (user decision 2026-11-25; was very low, 2026-11-22).** Since Nov22.8 the relay no longer sends rows back to the Sensor, so with no Monitor connected the rows reach nobody; one row per 10 s while the viewer status says no Monitor would cut the Sensor's mobile data (about 25 MB a day at one row a second) to a tenth, at the price of a coarser stored trail and a Sensor that depends on the viewer status.
*   **SIMP-NOV22.8-S2**: The Monitor's Foreground State. **Low priority (user decision 2026-11-25; was very low, 2026-11-22).** The Monitor keeps its relay connection in the background too (O122), so "a Monitor is connected" does not mean someone is looking. A Monitor -> Sensor message for foreground and background would let the Sensor send its rows faster or slower by it (two Monitors, lost connections and a killed Monitor to be handled).
*   **SIMP-NOV19.6-S1**: Compose's Own Text Fitting. Since Nov19.6 the HUD data keeps to one line through a private `OneLineFitText` in `HudStatusBar.kt` that measures the text with `rememberTextMeasurer` and steps the font down. Compose BOM 2023.10.01 has no `autoSize`; once the BOM is raised (with the Kotlin upgrade of ISSUE-NOV10.4-O72), `BasicText(autoSize = TextAutoSize.StepBased(6.sp, 9.sp))` would replace it. **Blocked by O72 (found 2026-11-23): `TextAutoSize` needs Compose foundation 1.8 (BOM 2025.04+), so Kotlin 2.x, the Compose compiler plugin, KSP, AGP and compileSdk come first.**
*   **SIMP-NOV9.3-S1**: R8 for the release builds (low priority, user decision 2026-11-23; explained 2026-11-25, the user took another item: best after O72, which changes Hilt's and Room's generated code, with the relay live for the socket and push checks). The release APKs already ship the Compose baseline profile (`assets/dexopt/baseline.prof`) and `profileinstaller` 1.3.0 through Compose and Activity (checked 2026-11-23); what is left is `isMinifyEnabled = true` with new `proguard-rules.pro` files (none exist yet) for kotlinx-serialization, Room, Hilt, osmdroid, socket.io and Firebase, checked on the phone with the release builds, since the tests run on debug.
