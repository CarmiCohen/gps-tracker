### 1. Lifecycle & Resource Management

*   **1.341 Alarming Setup & Alert Management Revival (R-ID 112)**: The system MUST provide fully revived Alarming Setup overlays (`AlertManagementOverlay` and `AlarmSoundOverlay` in `:core-ui`) supporting global mute, bulk toggles, communication/geofence/device/integrity/sentinel motion alarms, vibration/tilt sensitivity sliders, siren wave type selection, override DND/silent mode, force max volume, custom app volume controls, and persistent DataStore serialization across both Sensor and Monitor applications (R-ID 112).
*   **1.342 Device-Specific Setup & Hardware Hardening Revival (R-ID 113)**: The system MUST provide device-specific setup and hardware hardening (`DeviceProfileManager`, `DeviceHardeningStrategy`, `HardwareCapabilities`, and `PerformanceTier` in `:app-sensor`), automatically profiling hardware performance tiers (`STAGGERED` for budget tier hardware such as Samsung A15 vs `STANDARD`), enforcing vendor power management overrides, and applying the 60-second background transition hardening window (R-ID 113).
*   **1.343 System Tools & Diagnostics Menu Integration (R-ID 114)**: The system MUST provide a dedicated **Tools** menu option (refresh/tools icon button) positioned in the top menu bar alongside Setup and Settings gear icons in both Sensor and Monitor applications, opening `ToolsOverlay` (`:core-ui`) for 100Hz burst simulation, database pruning, test violation triggering, and watchdog resetting (R-ID 114).
*   **1.344 Revived Sound & Setup Options Integration (R-ID 115)**: The system MUST provide fully integrated `CleanSetupOverlay` and `PhoneSetupOverlay` components in `:core-ui`, wired into configuration menus in both Sensor (`AdminActivity`) and Monitor (`MonitorActivity`) applications to support system maintenance (clearing home points, resetting stats, triggering full initialization) and comprehensive device capabilities & permissions guides (R-ID 115).
*   **1.345 Upper Menu Line Expansion (R-ID 116)**: The system MUST provide an expanded upper menu line (top control bar) across both Sensor (`AdminActivity`) and Monitor (`MonitorActivity`) applications incorporating direct one-tap navigation for Setup (`Build`), Settings (`Settings`), Tools (`Refresh`), Map (`Place`), Events (`Menu`), Graphs (`Star`), and Info (`Info`) (R-ID 116).
*   **1.346 Monitor Hardware Deployment & Single-Line Fitting Audit (R-ID 117)**: The system MUST maintain single-line text layout constraints (`maxLines = 1`, `TextOverflow.Ellipsis`, compact button sizing of 28dp) across the upper menu bar (`AdminActivity` and `MonitorActivity`) and HUD status bars (`HudStatusBar`), ensuring zero line-wrapping distortion, full visibility of telemetry age metadata (`AGE:$ageStr`), and stable hardware deployment performance on S21FE and staggered tier devices (R-ID 117).
*   **1.347 Dual Device Hardware Deployment & Telemetry Audit (R-ID 118)**: The system MUST support simultaneous deployment and execution of `:app-monitor` on flagship tier hardware (S21FE) and `:app-sensor` on budget/staggered tier hardware (A155), maintaining background telemetry sampling intervals (10,000ms), zero-crash service lifecycle execution, and clean logcat event logging across both endpoints (R-ID 118).
*   **1.348 Decoupled Peer LED Signaling & Strict Relay-Independent Status Rules (R-ID 119)**: The system MUST strictly decouple peer connection LEDs from relay server connection LEDs across both Sensor and Monitor applications: `SRV` turns GREEN ONLY when actively connected to the Relay Server (otherwise RED); `TRK` on the Monitor side turns GREEN ONLY when connected to the TRACKER (`T`), independent of relay server state (otherwise RED); `VWR` on the Sensor side turns GREEN ONLY when connected to a VIEWER (`V`), independent of relay server state (otherwise RED) (R-ID 119).
*   **1.349 Nov4.44 Release Candidate Verification & Reciprocal Virtual Presence Simulation (R-ID 120)**: The system MUST execute all automated unit tests, hardening procedures, and stress evaluations (`test --warning-mode all`) with 100% passing results, enforce reciprocal virtual presence simulation testing in single-device environments, and lock full forensic state in baseline `STATUS/BASELINE/Nov4.44/` (R-ID 120).
*   **1.350 HUD Direction & Compact Spacing (R-ID 121)**: `HudStatusBar` MUST render left-to-right in layout and text order under every system language in both applications, and the Monitor MUST use its compact line spacing with no clipped text (R-ID 121).
*   **1.351 Real-Position Map Centering (R-ID 122)**: The Monitor map MUST center only on real device positions and MUST NOT use a hardcoded location: the local device when disconnected, the sensor when connected, and the locked device after `SENSOR` or `LOCAL` is tapped. With no position it shows the world view, and `(0,0)` rows are never drawn (R-ID 122).
*   **1.352 Telemetry Payload Integrity (R-ID 123)**: The signaling client MUST own a copy of every update it holds beyond `sendTelemetry`, and the wire format MUST carry position, timestamp, sequence, accuracy, speed, battery, charging, and temperature (R-ID 123).
*   **1.353 Viewer Presence & Relay Switching (R-ID 124)**: The client MUST consume `viewer_status_relay` to drive the `VWR` LED, and a relay URL change MUST close the old socket and connect to the new relay without an app restart (R-ID 124).
*   **1.354 Single Default Relay & Deployed Relay Parity (R-ID 125)**: Both applications MUST take the default relay address from `RelayConfig.DEFAULT_URL` (`https://gps-survival-relay.onrender.com`), and relay protocol changes in `relay-server` MUST be committed and deployed before a version that depends on them is verified (R-ID 125).
*   **1.355 Runtime Resilience (R-ID 126)**: The Sensor MUST continue sequence numbers after a crash and keep its wake lock renewed while running, and backfill requests and responses MUST be routable end to end (R-ID 126).
*   **1.356 Display Limits & Input Safety (R-ID 127)**: The Monitor MUST display at most the newest 1000 trail points at no more than 2Hz, show telemetry only from the paired device, keep all menu actions visible, and reject malformed relay URLs; instrument text MUST stay visible at the largest system font (R-ID 127).
*   **1.357 Forensic Entry Integrity (R-ID 128)**: Each `ForensicBuffer` entry MUST carry a checksum and damaged entries MUST NOT be returned; a sent sequence number MUST NOT be reused after power loss; a file format upgrade MUST keep stored entries; and code in `core-shared` MUST call only methods available at the Sensor's `minSdk` (R-ID 128).
*   **1.358 Real HUD Values (R-ID 129)**: Both Monitor HUD lines MUST show only real readings. The local line MUST use the Monitor device's own battery and position fix; a value that is not known MUST show as `--`, never as an invented number; and local speed MUST NOT be shown from a fix older than 35 seconds (R-ID 129).
*   **1.359 Bounded Trail Storage (R-ID 130)**: The Monitor MUST keep at most the newest 50,000 stored trail rows of each tracker, enforced by a background job scheduled at app start. Remote rows MUST be limited by count, never by age, so a tracker always keeps its newest rows and pruning never causes a false backfill (R-ID 130).
*   **1.360 Real Relay Status Text (R-ID 131)**: The Monitor Setup dialog MUST report the relay connection from the same state that drives the `SRV` LED, and MUST NOT show a fixed status or claim a connection it does not know (R-ID 131).
*   **1.361 Backfill Gap Recovery (R-ID 132)**: The Monitor MUST find missing telemetry from its stored trail, so a range that could not be requested or was never answered is requested again; a limit on requests MUST delay a range, never lose it; an unanswered request MUST be released; and the signaling client MUST NOT drop updates during a reconnect burst (R-ID 132).
*   **1.362 Real Version Strings (R-ID 133)**: Every version shown or logged by either application MUST come from the installed package. A version that cannot be read MUST show as `--`, and production code MUST NOT hold a release version in a string (R-ID 133).
*   **1.363 Unpair Confirmation (R-ID 134)**: No Monitor control MUST clear the pairing in one tap. Every control that unpairs MUST open one confirmation that names the tracker, and only its confirm action MUST clear the pairing; cancelling MUST keep it (R-ID 134).
*   **1.364 Real Sensor HUD Values (R-ID 135)**: The Sensor HUD MUST show the motion state, speed, accuracy, and age of the fix the Sensor service last received, using the same rule as the Monitor local line (rule 1.358). With the service stopped or before its first fix, these values MUST show as `--`, never as an invented number (R-ID 135).
*   **1.365 Monitor Alarms And Siren (R-ID 136)**: While a tracker is paired, the Monitor MUST raise an alarm when the tracker sends nothing for 35 seconds, reports no charging, reports a battery below 20%, or reports a temperature above 46°C, each only while its Alert Settings switch is on and Global Mute is off. An alarm MUST show full screen and sound the siren, with the saved Siren & Audio settings, until it is acknowledged, and MUST be raised again only after its condition has cleared. The alarm notification MUST use a high-importance channel that no other code can lower, and the Sensor MUST NOT play sound or vibrate (Rule 14, R872) (R-ID 136).
*   **1.366 Communication Alarms (R-ID 137)**: The Monitor MUST raise communication alarms for `Relay disconnected` when relay socket connectivity is lost (`signalingClient.isConnected` false), `Monitor internet lost` when local internet network capabilities report no active internet connection, and `Tracker GPS signal loss` when telemetry from the paired tracker reports `(0,0)` coordinates, 0 accuracy, or a `NO_FIX` / `GPS_SIGNAL_LOSS` status while online. Each MUST be switched by its respective Alert Settings toggle (`relayConnection`, `localInternet`, `signalLoss`) and Global Mute, sounding until acknowledged (R-ID 137).
*   **1.367 30-Second Siren Auto-Stop (Timer or Acknowledge) (R-ID 138)**: The Monitor siren MUST automatically stop after 30 seconds (`30s`) or when acknowledged, whichever occurs first. When the siren auto-stops via the 30-second timer, the visual alarm and notification MUST remain pending until explicitly acknowledged by the user (R-ID 138).
*   **1.368 False MOVING Fix & Sensor-Detected Violations (R-ID 139)**: The Sensor MUST run `SentinelLogic.validateMovement` with accelerometer motion (`hasPhysicalMotion`) on each fix to suppress GPS drift and false MOVING while stationary, and MUST transmit its motion state and violation status (`JUMP`, `OUTLIER`) in telemetry and via `ViolationEvent`. The Monitor MUST raise a GPS jump alarm (`AlarmType.GPS_JUMP`) when a violation or jump status is received, following `AlertSettings.jammerDetection` (R-ID 139).
*   **1.369 HUD Flow Rate-Limiting (R-ID 140)**: The Monitor `localHudState` and `remoteHudState` flows, as well as the Sensor `hudState` flow, MUST apply `atUiRate()` (500ms sampling window) to incoming telemetry and fix streams, capping UI state recalculations and emissions to at most 2Hz to prevent excess CPU usage, unnecessary IPC calls, and rapid recomposition (R-ID 140).
*   **1.370 Screen State & Rotation Preservation (R-ID 141)**: All Compose UI overlay visibility flags, dialog states, and map follow modes in `MonitorActivity` and `AdminActivity` MUST use `rememberSaveable` to ensure persistent state across screen rotation and configuration changes (R-ID 141).
