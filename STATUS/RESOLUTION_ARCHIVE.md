## ✅ Resolved Issues (Nov11.2-relay)
- **The Relay Tells When The Sensor Goes Silent (ISSUE-NOV10.8-O86, Medium, second version; stays open for a Monitor without a permanent connection)**: when the Sensor goes silent there is no row to push, so the relay now notices it by itself. **Relay v6.046** (`gps-survival-relay` commits `a5f2636`, `6bc386b`): `SilenceWatch` (`registry.js`) watches every Sensor from its first row; a one-second check finds a Sensor that sent no row for 35 s (`SENSOR_SILENT_MS`, the Monitor's `TRACKER_PRESENT_MS`; only `relay.test.js` shortens it by env) and reports it once per silence; the next row re-arms the watch and logs `[SILENT] Sensor '<id>' is back`. The report is pushed to the room's Monitors as a high-priority data message, key `notice`, text `{type: "sensor_silent", id, lastTs, lastSeq, silentMs}`, where `lastTs`/`lastSeq` are the newest row the relay got (an older queued row arriving late does not lower them). `index.js`: one `relayRow` for `location_update` and `location_batch` (the two copies merged), and one `pushToMonitors` for alarm rows and notices (one dead-token cleanup). `package.json` engines Node `24.x`: Render's first build of v6.046 failed because the repo has no lockfile and `firebase-admin` now pulls `@firebase/database-compat` 2.1.8, which needs Node >= 24.12 (new gap ISSUE-NOV11.2-O89). **Monitor**: `SensorSilenceWire`/`SensorSilence` (`core-network`) read the notice (null for another type, a missing `id` or `lastTs`, or non-JSON); `MonitorMessagingService` reads `notice` beside `row`, takes only the paired tracker's, logs `REV_Push` `Relay notice by push: tracker '<id>' sent nothing for <s> s (last row seq <n>)`, and starts the session; `PushedRows` keeps notices in a second channel under the same 30 s freshness rule (`offerSilence`, `freshSilences`); `alarmBooks` takes them as `silences` (last parameter, so positional callers are unchanged): a notice holds `TRACKER_OFFLINE` until a row newer than `lastTs` on the tracker's clock arrives, so the relay's replay of its cached last row on joining does not end it, and a notice about rows the Monitor has already outrun is ignored.
