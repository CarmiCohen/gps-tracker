# System Source of Truth (SoT) - Aug.03.100 (Metadata Header Implemented)

This document serves as the definitive operational specification. All Issue IDs are Authoritative.

### 1. Performance & Startup Authority
*   **Memory-Mapped Metadata Header Authority (R717)**: (Added Aug.03.100) The `ForensicSpillBuffer` MUST utilize a 128-byte persistent metadata header at the start of the file. This header MUST store `magicNumber`, `version`, `capacity`, `entrySize`, and `lastWriteRt`. The system MUST validate these fields during initialization to detect file corruption or schema mismatches, performing a full buffer reset if integrity is compromised. (Issue #717)
*   **Critical Battery Sentinel Authority (R716)**: (Added Aug.03.99) The system MUST monitor for abnormal battery discharge rates via the `isBatterySteepDischarge` flag. This condition MUST be correlated with high sensor activity (`vibration > 0.25G`) or high system load (`cpuLoad > 0.7`) to predict imminent shutdown. Alerts triggered under these correlated conditions MUST provide forensic metadata in technical details. (Issue #716)
*   **Persistence Health Alerting Authority (R715)**: (Added Aug.03.98) The system MUST monitor `forensicReliability` in real-time. If reliability remains below 0.85 for 30 consecutive seconds, an `ALERT_ID_PERFORMANCE_SPIKE` MUST be triggered. Note: This tracks the persistence layer success rate (the recorder), not physical events like chairsit. (Issue #715)
*   **Persistence Reliability Authority (R714)**: (Added Aug.03.97) The `LogRepository` MUST track successful vs. failed database flushes and calculate an EMA reliability factor (`forensicReliability`, 0.0 to 1.0). This metric MUST be exposed via `SystemHealthState` for diagnostic correlation. (Issue #714)
*   **Log Buffer Drain Throttling Authority (R713)**: (Added Aug.03.96) Forensic persistence flushes MUST be load-aware. The flush interval MUST scale dynamically (500ms to 5000ms) based on `cpuLoad`. Flushes MUST be inhibited when load exceeds 80% unless an emergency fill level (90%) is reached. (Issue #713)
*   **Adaptive Pruning Authority (R712)**: (Added Aug.03.96) The `LogRepository` MUST implement fill-level aware proactive pruning using dynamic thresholds (300 to 2000 entries) based on storage health and forensic sampling rates. (Issue #712)
*   **Forensic Persistence Correlation Authority (R711)**: (Added Aug.03.95) The `LogRepository` MUST correlate forensic convergence stalls with hardware health metadata (CPU load, I/O wait, Battery Temp) to facilitate diagnostic profiling. (Issue #711)
*   **Memory-Mapped Buffer Protection Authority (R710)**: (Added Aug.03.88) The `ForensicSpillBuffer` MUST implement a write-inhibit (Safe-Wrap) mechanism. If the buffer is full (`totalCount >= FORENSIC_SPILL_CAPACITY`), new traces MUST be dropped and an `ALERT_ID_FORENSIC_OVERFLOW` event MUST be logged. (Issue #710)
*   **Thermal-Aware Sampling Authority (R709)**: (Added Aug.03.85) Forensic sampling MUST be throttled to a minimum interval of 500ms (`FORENSIC_SAMPLING_INTERVAL_COOLING_MS`) whenever `isCoolingModeActive` is true. (Issue #709)
*   **Forensic Convergence Monitoring Authority (R708)**: (Added Aug.03.80) The `LogRepository` MUST monitor backfill convergence during forensic drainage. The system MUST log the remaining trace count after each database batch and trigger a warning if the buffer fails to clear. (Issue #708)
*   **Forensic Adaptive Flushing Authority (R707)**: (Added Aug.03.75) Forensic traces MUST be persisted to the database immediately when the `ForensicSpillBuffer` reaches 50% capacity (1,000 entries) or after a 5-second idle period. (Issue #707)
*   **Binary Trace Delta-Encoding Authority (R706)**: (Added Aug.03.70) Forensic traces MUST utilize header-based delta encoding for high-fidelity fields (`timestamp`, `lat`, `lng`). (Issue #706)
*   **Forensic Trace Deduplication Authority (R705)**: (Added Aug.03.65) To ensure exactly-once persistence of forensic traces across system restarts, the `LogRepository` MUST perform a signature-based deduplication check before database insertion. (Issue #705)
*   **Transactional Forensic Backfill Authority (R704)**: (Added Aug.03.55) Forensic traces MUST be drained from the spill-buffer using a transactional peek/commit pattern. (Issue #704)
*   **Forensic Recovery Integrity Authority (R703)**: (Added Aug.03.50) Forensic traces MUST include integrity validation to prevent recovery of corrupted data after crashes. (Issue #703)
*   **Trace Serialization Authority (R702)**: (Added Aug.03.47) Forensic traces MUST utilize full binary serialization for high-frequency capture. (Issue #702)
