# System Source of Truth (SoT) - Aug.19.08 (Production Validated)

This document serves as the definitive operational specification. All Issue IDs are Authoritative.

### 1. Performance & Startup Authority
*   **JNI Vendor Collision Remediation (R212)**: (Added Aug.19.01) The system MUST NOT utilize proprietary vendor keywords in any JNI identifiers, filenames, or class names to prevent framework-level collisions on Samsung devices (specifically SM-A155F). The hardware stabilization bridge MUST utilize a neutral namespace (`JdHardware`). (Issue #212). **Status: Implemented (Forensic complete; trigger identified as resilient OS heuristic).**
*   **Samsung Battery Authority (R405)**: (Added Aug.19.01) On Samsung hardware (specifically SM-A155F), the system MUST detect if the application is exempt from battery optimizations. If no exemption exists, the application MUST increment the System Issue Count and force the "Phone Setup" overlay to prevent OS-level service termination. (Issue #214). **Status: Implemented.**
*   **Final Release Validation (R211)**: (Added Aug.18.13) The system MUST undergo real-world moving validation on target hardware (Samsung A15) to verify thermal and battery stability at 100Hz forensic fidelity. Sustained capture MUST NOT trigger thermal throttling that compromises telemetry integrity. (Issue #211). **Status: Implemented.**
*   **Field Hardening & Thread Safety (R210)**: (Added Aug.18.12) The system MUST maintain strict thread-safety for all write counters to prevent race conditions during 100Hz forensic bursts. `MainRepository` MUST utilize `AtomicInteger` for trail and log write tracking. Forensic deduplication MUST utilize bit-packed `Long` signatures (`timestamp << 32 | spillIdx`) in a `HashSet` lookup to achieve O(N) efficiency and eliminate `Pair` object churn. (Issue #210). **Status: Implemented.**
*   **Production Fidelity Restoration (R209)**: (Added Aug.18.10) The system MUST operate at peak forensic fidelity following the stabilization of the UI and main-thread layers. Forensic sampling intervals MUST be restored to 100Hz (`10ms`) for peak fidelity and 10Hz (`100ms`) for power-aware states in `EngineConstants`. Hardware IMU listeners in `AppSensorManager` MUST utilize `SENSOR_DELAY_FASTEST`. (Issue #209). **Status: Implemented.**
*   **UI Allocation Churn Mitigation (R208)**: (Added Aug.18.09) The system MUST eliminate high-frequency object allocations in the UI layer to prevent GC-induced frame hangs. The `MainViewModel` MUST implement a trail segment cache that skips O(N) simplification logic if the source trail size hasn't increased. The `MapOverlayManager` MUST utilize a `circleCache` for `GeoPoint` lists to eliminate redundant allocations of circle geometries (approx. 60 points per circle) during map invalidation cycles. (Issue #208). **Status: Implemented.**
*   **Main-Thread Hang Remediation (R207)**: (Added Aug.18.09) The UI MUST remain responsive during high-frequency system pulses. Map freshness indicators in `AppMapContainer` MUST be gated using `derivedStateOf` to prevent full Compose recompositions when geographic data is static. The imperative MapView update block MUST be wrapped in `Snapshot.withoutReadObservation` to decouple Compose state tracking from imperative osmdroid overlay management. (Issue #207). **Status: Implemented.**
*   **Forced LTR Layout Authority (R205)**: (Added Aug.18.08) Technical telemetry and numbering MUST always be rendered in Left-to-Right (LTR) direction to prevent BiDi artifacts. Technical overlays MUST be wrapped in an LTR `CompositionLocalProvider`. (Issue #205). **Status: Implemented.**
*   **Permission Navigation Hardening (R206)**: (Added Aug.18.08) The system MUST provide a robust path to system permission settings, implementing fallbacks if specific intent URIs are rejected by the OS. (Issue #206). **Status: Implemented.**
*   **Diagnostic Stress Isolation Authority (R204)**: (Added Aug.18.08) The system MUST support a temporary diagnostic down-sampling state to isolate the impact of high-frequency sensor processing. (Issue #204). **Status: Superseded by R209.**
*   **Forensic Multi-Session Alignment Authority (R203)**: (Added Aug.18.07) The system MUST guarantee temporal monotonicity for forensic traces across service restarts. (Issue #203). **Status: Implemented.**
*   **Forensic Allocation Optimization (R202)**: (Added Aug.18.06) The system MUST eliminate intermediate heap allocations during forensic log draining using the `peekToEntities` zero-churn path. (Issue #202). **Status: Implemented.**

### 2. Forensic Persistence Authority
*   **Zero-Loss Spill Buffer (R200)**: The system MUST utilize a memory-mapped circular buffer for forensic telemetry to ensure durability across process crashes. (Issue #196).
*   **CRC32 Integrity Authority (R201)**: Every forensic entry MUST include a CRC32 checksum for post-recovery validation. (Issue #203).

### 3. UI & Map Authority
