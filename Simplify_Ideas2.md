# Simplification Ideas 2.0 (Aug.30.12)

*   **ManagedHardware Ecosystem (R750-R757) - COMPLETE**: Implemented specialized lifecycle-aware wrappers for Network, Location, GNSS, Sensors, and Broadcast receivers. This ensures deterministic native resource cleanup by forcing unregistration to occur on the dedicated hardware thread (or Main Looper for OS callbacks) before component termination, preventing orphaned native listeners.
*   **Fallback Unregistration Hardening (R767/R775) - COMPLETE**: Added synchronous direct unregistration paths in `ManagedHardware` to handle scenarios where hardware threads are unresponsive during shutdown. Enforced "Zero-Raw-Unregistration" (R775) to prevent native `BaseEventQueue` leaks during power-state transitions and service termination.
*   **Map Hydration Gating (R758) - COMPLETE**: Resolved significant startup ANRs by offloading heavy OSMDroid engine initialization and `SqlTileWriter` pre-warming to a background IO thread. Integrated a thread-safe `isOsmReady` gate to prevent Main thread hydration attempts before native binding is stable.
*   **Async Geometry Generation (R758b) - COMPLETE**: Offloaded complex circle and geofence polygon point calculations to `Dispatchers.Default`. This ensures the UI thread remains at a consistent 60FPS even during high-frequency (10Hz) telemetry updates, eliminating frame skips on budget hardware.
*   **Segmented Overlay Population (R776/R777) - COMPLETE**: Applied a segmented coroutine pattern with `yield()` to violation and home point marker instantiation. By spreading marker creation over multiple UI frames, we successfully eliminated 1500ms+ "Davey" stalls observed on Samsung A15 hardware during heavy history hydration.
*   **Unified Hardware Registry (R760) - COMPLETE**: Consolidated legacy `GpsManager` and `AppSensorManager` into a single `HardwareProvider`. By sharing a single optimized `HardwareThread`, we reduced context-switching overhead and simplified the hardware lifecycle handshake.
*   **Engine Config Unification (R764) - COMPLETE**: Decommissioned the redundant `DeviceSpecialFlags` class. All hardware-specific logic now utilizes the engine-level `HardwareCapabilities` model directly, improving architectural purity.
*   **Acoustic Logic Encapsulation (R762b) - COMPLETE**: Extracted adaptive duty-cycle calculations into a pure function (`computeAdaptiveAcousticOffCycle`) in `SentinelValidator.kt`. This improves testability and decouples the monitoring loop from hardware side-effects.
*   **Stationary Transparency (R765) - COMPLETE**: Integrated definitive `[ULTRA]` visual indicators into the HUD and notifications. This provides users with clear transparency regarding relaxed GNSS polling intervals during long-term stationary periods.
*   **Technical UI Directionality (R766) - COMPLETE**: Enforced LTR direction for all technical telemetry components using `CompositionLocalProvider`. This ensures forensic readability and prevents asymmetric data misalignment on devices using RTL locales.
*   **[Stationary Derivation Logic] - EVALUATED (Aug.30.09)**: Determination: The `isUltraLongStationary` flag MUST be retained in the telemetry payload. Deriving this state solely on the Viewer side lacks the IMU fidelity required for accuracy and introduces high state-mismatch risks during 5-minute relaxed polling intervals. Transparency and State Parity are prioritized over minor payload savings.
*   **IPC Identification (R759)**: Continue identifying system-level lookups (UID, ProcessInfo) that might be triggering hidden OS diagnostic spam and migrate them to the `GpsApplication` shadow-caches.
*   **Segmented Marker Initialization**: Evaluate if home point markers (Level 4) should also be segmented if the count exceeds 10, maintaining consistency with trails and violations.
